🌐 API Basics

A Beginner's Guide to Understanding APIs

📚 Key Definitions

API (Application Programming Interface) A set of rules that allows two programs to communicate with each other. Think of it like a restaurant menu—you (the client) request items from the menu, and the restaurant (the server) prepares and delivers them.
Server A computer program that waits for requests from clients and sends back responses. It's like a restaurant kitchen that receives orders and prepares food.
Client A computer program that makes requests to a server. It's like a customer ordering food from a restaurant.
HTTP (HyperText Transfer Protocol) The language/rules that clients and servers use to communicate over the internet. It's the standard protocol for web communication.
GET Request A request to retrieve or read data from a server. It's like asking "Can I have the menu?" or "Tell me what items you have." GET requests don't change anything on the server—they just fetch information.

Example: Getting the current weather, reading a blog post, fetching a list of users
POST Request A request to send or create data on the server. It's like saying "Here's my order" or "Please save this information." POST requests can change data on the server.

Example: Submitting a form, uploading a file, creating a new user account
Endpoint A specific URL path on a server that performs a particular action. Think of it like a specific service counter in a store.

Examples: /string, /json, /echo-string, /echo-json
Response The data that a server sends back to a client after processing a request. It includes a status code (indicating success or failure) and the requested data.
Status Code A three-digit number that tells you the result of a request:
• 200 = Success (request worked perfectly)
• 404 = Not Found (endpoint doesn't exist)
• 400 = Bad Request (something wrong with your request)

💡 How APIs Work

The Big Picture:

An API is like having a conversation between two programs. One program (the client) asks a question or makes a request, and another program (the server) listens, processes the request, and sends back an answer. This conversation happens over the internet using HTTP—a standardized protocol that both programs understand.

Step-by-Step Flow

1
Client Prepares a Request
The client decides what information it needs and creates a request (GET for reading, POST for sending).
2
Client Sends Request to Server
The request travels across the internet to the server, including the endpoint, method (GET/POST), and any data being sent.
3
Server Receives & Processes
The server receives the request, understands what the client wants, and processes it (fetches data, saves data, runs calculations, etc.).
4
Server Sends Response
The server sends back a response that includes a status code (was it successful?) and the requested/processed data.
5
Client Receives & Uses Response
The client receives the response and uses the data (displays it, stores it, processes it further, etc.).

🛠️ Implementation Requirements Matrix

What You Need to Build:

Below is a detailed matrix showing what components and libraries are required to build an API with both barebones HTTP and FastAPI approaches. This shows the fundamental difference between building from scratch vs. using a framework.
Server Requirements
Component Barebones HTTP FastAPI
Core Library http.server (Python built-in) fastapi + uvicorn
Handler Class Inherit from BaseHTTPRequestHandler Define functions with decorators (@app.get, @app.post)
HTTP Methods Write do_GET(), do_POST() methods Decorators automatically handle methods
Request Parsing Manual: self.rfile.read(), json.loads() Automatic: Type hints handle conversion
Response Sending Manual: send_response(), send_header(), wfile.write() Automatic: Return Python objects, FastAPI converts to JSON
Error Handling Manual: try/except for each endpoint Built-in with HTTPException
CORS Support Manual header manipulation required Built-in with CORSMiddleware
Server Startup HTTPServer().serve_forever() uvicorn.run(app, host, port)

POST Requests Create Request() object with data Create Request() object with data

Key Insight:

Notice that the client code is essentially identical for both approaches! The client doesn't care whether the server is using barebones HTTP or FastAPI—it just sends HTTP requests using urllib. The real difference is on the server side: FastAPI makes writing servers much easier and less error-prone by handling many details automatically.

This demonstrates why frameworks exist: they reduce boilerplate code, provide built-in best practices, and let you focus on your actual application logic rather than HTTP plumbing.

✨ Summary

Remember:

• An API is a way for two programs to talk to each other
• The server listens and responds to requests
• The client makes requests and processes responses
• GET = asking for information (read-only)
• POST = sending information to be stored or processed
• HTTP is the language they use to communicate
• Frameworks like FastAPI make building servers much easier
