Source summary & data-transfer methods

The backend is the only component that talks to these sources. The frontend and the LLM never call them directly.

SourceRole in the hierarchyTransfer methodEndpoint / accessAuthFormat
Official FPL API — bootstrap-static Primary source for FPL-specific data: identity, price, ownership, points, minutes, availability, transfers, gameweeks, official FPL xG/xA fields REST API — HTTP GET, polled by the backend GET https://fantasy.premierleague.com/api/bootstrap-static/ (~1 MB, one payload) None JSON
Official FPL API — fixtures Primary source for fixture list, kick-offs, results and FDR REST API — HTTP GET GET https://fantasy.premierleague.com/api/fixtures/ (or ?event={gw}) None JSON
Official FPL Price Change Predictor Price-rise/fall progress — checked in every weekly analysis; feeds transfer-timing advice REST API — HTTP GET (same bootstrap-static payload; refreshed by FPL every ~15 min) Surfaced as the price_change_* fields on each player in bootstrap-static, plus game_config.settings.price_change_deadlines None JSON
Official Premier League / club sources Authoritative team news: injuries, suspensions, manager quotes, confirmed XIs Web retrieval — HTTP GET of official pages / RSS feeds, parsed by the backend (no public JSON API); manual entry as an initial fallback premierleague.com news & club official sites (URLs configured per club) None HTML / RSS → parsed to structured records
Understat Canonical source for underlying performance data (xG, xA, npxG, shots…) Web scraping — HTTP GET of Understat pages; JSON embedded in page <script> tags is extracted and parsed (no official API) https://understat.com/league/EPL, /team/{name}/{season}, /player/{id} None HTML with embedded JSON

Pipeline

Official FPL APIidentity, price, ownership, FPL points, minutes, starts, fixtures, FDR, availability, transfers, official xG/xA
Official PL / club sourcesinjuries, suspensions, manager comments, predicted/confirmed selection, team news
Understatunderlying attacking/defensive process: xG, xA, npxG, npxG+xA, shots, key passes
Derived fieldsminutes reliability, per-90 rates, points/£, xG/£, fixture-adjusted projections, opportunity cost, price-rise interpretation, BUY/HOLD/WAIT

API conventions to remember

  • Prices are integers ×10 — now_cost: 60 = £6.0m (game_settings.ui_currency_multiplier = 10).
  • Many numeric stats arrive as strings (form, selected_by_percent, expected_*, ep_next…). Cast to float/Decimal in Pydantic models. *_per_90 fields are real floats.
  • id is season-specific; code is permanent. Join on id within a season, use code for cross-season history.
  • Timestamps are ISO 8601 UTC. The FPL API has no official documentation — re-fetch and diff field names at the start of each season.
